# Проверка тарифов аэропортов — задание проверяющему

Другой исследователь собрал тарифы аэропортов в JSON (`out/<ICAO>-<год>.json`) и вёл журнал (`trace/<id>.jsonl`).
Ты в сборе не участвовал. Рабочая папка: `charges`.

Для каждого файла тарифа из твоего списка:
1. Открой `source_url` (WebFetch; длинные PDF — с `offset`). Проверь, что это действующий документ этого аэропорта,
   год/дата действия совпадает с `valid_from`.
2. Сверь с документом КАЖДОЕ правило, у которого `rate` больше нуля: ставка, валюта, единица (`base`), признак
   начисления (`events`: landing / movement / takeoff / turnaround), условия `when`. Для правил с одинаковой
   структурой (полосы массы, группы стоянок) достаточно сверить таблицу целиком по 2–3 строкам с краёв и середины.
3. Шаги `extract` журнала с адресом этого документа: найдена ли цитата (не дословно из-за разметки PDF — допустимо,
   если числа и подписи совпадают).

Итог — `verify/<файл без .json>.json`:
```json
{"doc_ok": true, "doc_note": "", "rules_checked": 12, "rules_ok": 11,
 "errors": [{"rule": "code/base/when кратко", "file": "что в файле", "doc": "что в документе", "fix": "как исправить"}],
 "unreachable": false, "note": ""}
```
`errors` — только расхождения с документом (ставка, база, признак начисления, условие, валюта). Сомнения без
доказательства — в `note`. Не меняй файлы в `out/` и `trace/`. Документ не открылся — `unreachable: true`.
В ответе — сводка до 200 слов: по каждому файлу ok / ошибки (главные), что не проверено.
