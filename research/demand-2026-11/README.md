# Исследование спроса: данные для сценариев 2029, 2031 и 2036

Действующая постановка — `FORECAST_PLAN.md`, границы завершённого пилота — `SPEC.md`.
Этап 0056-v2 собирает длинную историю, предложение рейсов и внешние предпосылки, включая население
по стране рождения. Этап 0057 уже измеряет ошибки простых прогнозов на 3/5/10 лет
и изменения частоты/вместимости. Собственные прогнозы рынков на 2029/2031/2036 ещё не выпущены. Новые слои описаны в `SUPPLY_DATA.md` и `MIGRANT_STOCK.md`.

## Воспроизвести новый сбор

Из корня проекта, в его окружении Python:

```bash
python research/demand-2026-11/collect_panel.py \
  --raw-dir ../research-inputs-0056 --fetch all
```

Параметр `--fetch` принимает также отдельные группы `base`, `routes`, `regional`, `visa_history`.
Уже скачанный кеш используется повторно; `--refresh` запрашивает новую версию. Кеш обязательно находится
вне репозитория. Каждый ответ ограничен 50 МБ, история выгружается страницами с проверкой полноты.
Без `--fetch` команда пересобирает результаты из существующего кеша и не обращается к сети:

```bash
python research/demand-2026-11/collect_panel.py --raw-dir ../research-inputs-0056
```

Выходы:

- `out/data_inventory.json` — инвентарь базового сбора 0056 с периодами, единицами, версиями, доступом и пробелами.
- `out/collection_summary.json` — полнота годов базового сбора, отсутствующие месяцы, группы ошибок качества,
  число допустимых исторических точек отсчёта и недостающих целевых фактов.
- `out/eu_monthly_panel.json.gz` — производные месячные пары Eurostat из явно указанного архива DBnomics;
  встречные отчёты усреднены, флаги сохранены.
- `out/eu_excluded_groups.json.gz` — неизвестные/системные места, центры управления и self-пары;
  они сохранены для аудита и исключены из покрытия конкретных аэропортных пар.
- `out/regional_history.json.gz` — региональный доход, население, занятость, месячные ночёвки и флаги источника.
- `out/india_*_panel.json.gz` — внутренние месячные и международные квартальные пары городских названий DGCA.
- `out/country_history.json.gz` — исторические страновые показатели WDI; это не прогноз.
- `out/scenario_inputs.json.gz` — внешние WPP/WEO-сценарии; это не наши прогнозы маршрутов.
- `out/visa_snapshots.json.gz` — датированные визовые снимки; старые коды 2019/2020 пока не сведены
  с новой классификацией, текущий режим не переносится в прошлое.

В JSON внутри каждого gzip указаны колонки, единицы и политика пропусков. Сжатие детерминированно.
Панели Индии адаптированы из сборки DGCA/Vonter и остаются под **ODbL 1.0** с указанием обоих источников.
Остальные права и первичные адреса сохраняются в метаданных соответствующих источников.

Проверить контрольные суммы полученного набора:

```bash
python - <<'PY'
from pathlib import Path
import hashlib
import json

out = Path("research/demand-2026-11/out")
inventory = json.loads((out / "data_inventory.json").read_text())
for artifact in inventory["derived_artifacts"]:
    path = out / artifact["file"]
    assert path.stat().st_size == artifact["compressed_bytes"], path.name
    assert hashlib.sha256(path.read_bytes()).hexdigest() == artifact["sha256"], path.name
print("Панели соответствуют инвентарю")
PY
```

Каждая исходная страница имеет отдельный URL и SHA-256 в метаданных инвентаря. При `--refresh` версия
источника может измениться: новый набор нужно проверять заново, а не объявлять прежним снимком.
Для WPP включена поправка Medium для Того от 19.01.2026; его Low/High в этом обновлении не пересмотрены
и помечены предупреждением о несопоставимости. Население WPP — на 1 июля, переведено из тысяч в человек;
население WEO сохранено в опубликованных миллионах, что явно указано у каждой строки.

При ранней проверке один прямой запрос Eurostat вернул HTTP 200 с HTML технической недоступности;
это сохранено как ошибка содержимого. Последующие проверки 0056-v2 показали, что прямой API работает:
точечные запросы предложения и все пять ограниченных запросов `migr_pop3ctb` вернули корректный JSON.
Большой запрос истории рейсов Германии вернул HTTP 413 `ASYNCHRONOUS_RESPONSE`; это ограничение
данного запроса, а не доказательство общей недоступности Eurostat.

Длинная транспортная панель получена через явно названный архив DBnomics. Для нового слоя предложения
3 795 значений выборочных первичных рядов совпали с архивом; это не сплошная первичная сверка всех пар.
Дата Eurostat, дата индекса зеркала и дата скачивания различаются. Транспортный архив заканчивается
декабрём 2024 года. Пять проверок рейсов с января 2025 года вернули пустую ось времени; это результат
конкретных запросов, а не утверждение об отсутствии свежих данных во всех источниках. Производственный
парсер хранит последние 36 месяцев: серверная БД полезна для свежего продолжения, а не как замена архиву.

Оба сборщика используют сохранённый кеш, если он уже есть. Без `--fetch` они работают только с этим

Новые слои имеют собственные сводки и хеши: прежний `data_inventory.json` их ещё не описывает.

Предложение измерено отдельно от прежнего потока on-flight O&D: `PAS_BRD / ST_PAS` даёт занятость
кресел на участке, `ST_PAS / CAF_PAS` — среднее кресел на рейс. Для отношений используются одни и те же
отчётчики с полной тройкой; встречные сообщения усредняются, не складываются. `PAS_CRD / ST_PAS`
не подставляется вместо занятости. Средняя вместимость не определяет тип самолёта.

Население по стране рождения получено напрямую у Eurostat для DE/ES/FR/IT/NL: 13 820 числовых ячеек,
из них 11 513 по отдельным странам/территориям. Включены опубликованные нули и сохранены все пропуски
и флаги. По Германии в этом срезе есть лишь групповые итоги; индивидуальные страны рождения отсутствуют.
Полные 21 год имеют 222 индивидуальные категории Италии, 200 Нидерландов и 52 Испании; у Франции
охват меняется. Это запас населения на 1 января, а не гражданство, число поездок или уже оценённый
вклад диаспор в спрос. Подробности — `MIGRANT_STOCK.md`.

## Пересчитать без сети

Из корня проекта, в его окружении Python:

```bash
python research/demand-2026-11/benchmark.py
```

Используются зафиксированные `research/routes-2026-11/out/pairs_eu.json`, `airports.json`, а также
`out/income_covariates.json` и `out/tourism_covariates.json`. Для каждой строки результата в
`out/predictions.jsonl` сохранены пара, факт, прогнозы и номер проверочной группы. По этому файлу можно
независимо пересчитать метрики, не вызывая функции модели. Контрольные суммы входов — в `summary.json`.

Задачи разделены: прогноз 2024 для пары с историей 2023 и проверка полностью скрытой пары 2024 с известными
другими потоками её аэропортов. У второй нет прогноза «как в прошлом году». Все числа — пассажиры в год
в обе стороны; деление на 12 не является оценкой сезонности.

## Что потребуется с сервера для продолжения

`export_panel.py` использует только стандартную библиотеку. База открывается с `mode=ro` и
`PRAGMA query_only=ON` в согласованной read-транзакции. Экспортируются только комбинации домена и источника
из явного списка: пассажиропоток, публичные аэропорты/города и исследовательские макрофакторы.

Файл содержит все сохранённые версии разрешённых фактов, происхождение, состояния источников и покрытие
по годам. Исследователь выбирает версии явно; дата наблюдения не равна дате публикации. Сообщения об ошибках,
локальные пути, сырые документы, параметры URL и реквизиты доступа исключены. Пользовательские рабочие места,
настройки, бот и API-файлы вообще не читаются.

После установки патча выполнить **на сервере**:

```bash
sudo -u fcabot /srv/fca/venv/bin/python \
  /srv/fca/app/research/demand-2026-11/export_panel.py \
  --db /srv/fca/master/flightcost.db \
  --traffic-since 2024-01-01 \
  --out /tmp/fca-demand-panel-20261111.jsonl.gz
```

Скачать на свой компьютер:

```bash
scp deploy@178.253.52.205:/tmp/fca-demand-panel-20261111.jsonl.gz ~/Downloads/
```

Это один сжатый файл для свежего продолжения архива и восстановления полной P/T/F. В рамках сбора 0056-v2
команда на сервере не выполнялась; она понадобится, если актуальные входы нельзя получить публично.
В публичный репозиторий выгрузку не добавлять. Существующий файл
экспортер не перезаписывает: для повторной выгрузки нужно другое имя. По умолчанию поток берётся с
2019-01-01, в команде выше явно выбран свежий период с 2024-01-01; справочники и макрофакторы — со всей
сохранённой историей. Отсутствующие источники перечислены
в конце вывода и в последней строке архива.

## Условия интерпретации

- Eurostat PAS_CRD — on-flight O&D аэропортов, а не полная поездка человека с пересадками.
- Годовые агрегаты включают пары с 12 положительными месячными значениями. Открытие/закрытие маршрутов
  и скрытый спрос отсутствующих направлений этим benchmark не проверяются.
- Масса узла — доступные опубликованные пары, а не официальный полный оборот аэропорта.
- Основная модель обучается в логарифмах. Диагностический `gravity_smearing` использует среднее
  `exp(остаток)` только обучающей части; улучшение общей суммы не гарантирует улучшения отдельных пар.
- ВВП и ночёвки добавлены в разные группы полного покрытия. Каждый эффект сравнивается с базовой моделью
  на той же группе, не по абсолютным ошибкам разных групп.
- Один фиксированный split не доказывает причинный эффект, устойчивость на новом аэропорте или отсутствие
  эффекта фактора в другой спецификации. Сезонность, деловая активность, диаспоры и визы пока не оценены;
  новые панели предложения и страны рождения готовят входы для этой проверки.

## Расчёты 0057

`MODEL_RESULTS.md` описывает временные разбиения, модели, метрики, выбытие наблюдений,
интервалы и сопоставление предложения. Все входы — сохранённые панели; сеть не требуется.
Для пересборки HTML нужен Python 3.12 или новее; готовые три языковые версии включены
в патч. Числовые расчёты работают отдельно от HTML-сборщика.

```bash
python research/demand-2026-11/forecast_benchmark.py
python research/demand-2026-11/route_evolution.py
python research/demand-2026-11/verify/verify_modelling_0057.py
python research/demand-2026-11/build_report.py
```

Основной вариант benchmark: годовой лаг публикации, пять полных обучающих лет,
3/5/10 лет от решения. Пропущенная цель не считается нулём. Основной десятилетний тест
имеет только цели 2020–2024 и не измеряет обычный доковидный цикл. Архив пересмотрен
современным выпуском; исторические винтажи не восстановлены. Это ещё не тест всей P/T/F.

Эволюция предложения рассчитана на одной когорте 1 537 пар с одинаковыми отчётчиками
и полными 2015/2019/2024. Укрупнение неравномерно по расстоянию; среднее число кресел
не идентифицирует тип или прибыль авиакомпании. Источники и маршрутные сценарии —
`out/route_aircraft_evidence.json`, `out/route_aircraft_copy.json`, `trace/route_aircraft_0057.jsonl`.
Глава `modelling_update.py` собирается из вычисленных JSON, `aircraft_demand_section.py` —
из первичных фактов и отдельно подписанных сценарных предпосылок.

Независимая проверка расчётов: `verify/modelling_0057.json`. Входы и происхождение
проверялись в 0056-v2; старые аудиты сохраняют исторический статус.
Проверка трёх языковых версий, числовых таблиц, SVG и маршрутных сценариев:
`verify/report_0057.json`. Статическая визуальная проверка и её ограничения:
`verify/visual_0057.json`.
