# 0060 — инвестиции как ранний сигнал авиационного спроса (исследовательский пилот)

**Статус:** проект источников и первый открытый country-level snapshot. НЕТ оценки влияния на пассажиров, прогнозов маршрутов и изменений калькулятора. Это дополнение к существующему исследованию спроса (0059), не новая страница.

## Зачем

Долгий прогноз 2029/2031/2036 должен учитывать реальные изменения экономики территории, которые нельзя увидеть из прошлых рейсов: гостиницы и курорты, заводы, промзоны, логистические центры, аэропорты, добыча и энергетика. Но сумма объявленных инвестиций — плохой непосредственный прогноз пассажиропотока: финансирование может не состояться, строительство может задержаться, спрос может перераспределяться из соседних городов или аэропортов.

## Изучаем не деньги в целом, а цепочку событий

```mermaid
flowchart LR
  A[Анонс проекта] --> B[Финансирование]
  B --> C[Строительство]
  C --> D[Ввод в эксплуатацию]
  D --> E[Места / номера / производство]
  E --> F[Поездки работников, туристов, партнёров]
  F --> G[Зона аэропорта и маршруты]
  G --> H[Частота, кресла, типы ВС]
```

- **Туризм:** число *новых* гостиничных номеров, дата открытия, загрузка, сезонность, различие городской и курортной гостиницы, доля новых гостей и каннибализация существующих мест; инвестор из страны X не обязательно означает туристов из страны X.
- **Промышленность:** этап стройки (временные поездки подрядчиков), производственный этап (сотрудники/поставщики), местные или приезжие кадры, реальные источники и направления деловых поездок. **CAPEX ≠ годовой пассажиропоток.**
- **Нефтегаз/энергия/добыча:** поездки специалистов могут иметь иной сезонный профиль и маршрутный рисунок; посёлки с вахтовыми рейсами нельзя автоматически экстраполировать на массовый рынок.
- **Транспортная инфраструктура:** новый аэропорт или дорога может **перераспределить** существующий спрос, а не создать его; иногда новая железная дорога уменьшает авиационный спрос.

## Первый слепок: гостиничные проекты Африки

`hotel_pipeline_africa_2026.csv` — десять публично приведённых стран из W Hospitality Group, отчёт от **10.03.2026**, [публичная таблица](https://www.thebench.com/insights/report-highlights-hotel-chain-development-pipelines-in-africa-2026). Это не полная база объектов: для всей Африки в отчёте **675 гостиниц и 123 846 номеров**. У нас лишь десять крупнейших стран и приблизительная стадия «в строительстве», без названия гостиницы, места, пассажирского источника и гарантированной даты ввода.

Использовать только для первичной разведки и выбора регионов. Нельзя умножать `rooms_pipeline × 2 × число рейсов` — неизвестны добавочная загрузка, импорт туристов, повторное размещение существующего спроса и доля прилетающих самолётом.

### Локально проверить/построить JSON-сводку

Из корня проекта, без API-ключей и без сторонних библиотек:

```bash
python research/demand-2026-11/investments/pilot.py --as-of 2026-11-12 \
  --out research/demand-2026-11/investments/pilot_2026_summary.json
python -m unittest discover -s research/demand-2026-11/investments -p 'test_*.py' -v
```

**Защита от знания будущего:** `--as-of 2025-12-31` честно вернёт пустой результат для слепка, впервые опубликованного в марте 2026. Нельзя использовать агрегаты из редакции 2026 года в обучении исторического прогноза «по состоянию на 2020 год». Для такой проверки нужны *архивные редакции*, известные на каждую историческую дату.

`project_signal.schema.json` определяет будущий проектный набор: отдельная запись для каждого опубликованного события, известная дата публикации, статус, уровень географической точности, объявленная/законтрактованная/фактически потраченная сумма, ёмкость проекта, ориентир открытия, страны инвестора и подрядчика (если известны). Незаполненные поля — `null`, а не придуманные значения.

## Что делаем следующим этапом

1. Собрать **исторические версии инвестиционных планов** и их фактические открытия, выделить отменённые и замороженные проекты. Приоритет — страны с проверяемым авиафактом: Египет, Марокко, Кения, Танзания и островные курортные рынки; Эфиопию проверить отдельно как hub/деловую географию.
2. Получить **точные координаты** хотя бы для 50–100 проектов из источников с правом использования, вычислить доступность 2–4 ближайших аэропортов по дороге, а не только по расстоянию по прямой. Предварительно можно использовать геокодированные AidData/GEM; у страновой гостиничной таблицы этой точности нет.
3. Сформировать для каждого года «факторы, которые были известны тогда» (`published_at <= forecast_as_of`). Классы: предварительный анонс, подтверждённое финансирование, строительство, эксплуатация, приостановка/отмена. **Вероятности завершения и временные лаги оценить по историческим данным**, не назначать произвольные коэффициенты к потокам.
4. Сравнить двух кандидатов: `baseline` (без инвестиционных признаков) vs `baseline + проекты`. Качество измерять на идентичных парах и периодах, отдельно для известных и новых направлений, плюс отрицательные контроли: отменённые проекты, симметричные соседние аэропорты, иллюзорные анонсы.
5. Только если появляется воспроизводимое улучшение — показать интервал Δпассажиров, затем оптимальные частоты и типы ВС в калькуляторе **как явный сценарий**. Не менять P/T/F до прохождения проверки.

### Чему нужно уделить особое внимание

- **Обратная причинность:** отели часто строятся потому, что туризм УЖЕ растёт. До включения признака проверять, добавляет ли он что-либо сверх предыдущих пассажирских и туристических показателей.
- **Двойной счёт:** один проект может встретиться в World Bank, IATI, MapAfrica и GEM, а $1 млрд финансирования нельзя дважды считать в общем сигнале. Использовать устойчивый project-id и сопоставлять документы.
- **Конкуренция:** инвестиции могут изменить выбор аэропорта, перевозчика, пересадки, наземного маршрута и перевозки между городами.
- **Риск и интервалы:** результат должен иметь консервативный/базовый/ускоренный сценарий, но веса этих сценариев нужно подтверждать данными.

**Прототип не подключается к серверу, не запускает агентов и не является поводом менять текущие прогнозные коэффициенты.**
