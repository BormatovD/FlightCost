# 0061 — IATI Datastore: подтверждённые события финансирования (исследование спроса)

> **Внимание после 0064-B:** примеры команд ниже описывают первоначальную версию 0061–0063. Теперь для любого живого обращения обязателен `--budget-db`; многостраничная загрузка запрещена до проверки стабильной сортировки. Выполняйте обновлённые команды из `README-0064-B.md`. Не запускайте старые инструкции без учёта общего бюджета.

**Цель:** начать собирать *датированные доказательства* по инфраструктурным и туристическим проектам для прогноза маршрутов 2029/2031/2036. Этот патч дополняет 0060, не меняет калькулятор, бота, OpenClaw или расписания.

## Что это за источник

IATI — отчётность международных организаций о финансировании развития. **Это не полная база иностранных частных инвестиций**, не реестр всех заводов и не обещание появления рейсов. В реальной записи могут быть несколько стран, разные подрядчики, суммы в разных валютах и неоднократная публикация одних денег несколькими организациями.

Используем официальный **Datastore v3**:

- endpoint: `https://api.iatistandard.org/datastore/activity/select`
- параметры: `q`, `rows`, `start`, `fl=iati_identifier,iati_json`, `wt=json`; неподтверждённая сортировка `sort=activity_id asc` из версии 0061 убрана в исправлении 0062
- ключ передаётся **только HTTP-заголовком** `Ocp-Apim-Subscription-Key`, не в URL, stdout, конфигурации Git или файлах данных;
- IATI Exploratоry — до **5 запросов в минуту и 100 в неделю**; Full Access требует отдельного согласования;
- каждая страница — не больше 1000 строк по контракту API; скрипт намеренно ограничивает пилот 100 строками и 3 страницами на страну, по умолчанию — 30 × 1; **до проверки устойчивой сортировки используйте только `--max-pages 1`**, так как несколько страниц могут пересечься при изменениях индекса;
- идентификаторы проектов, виды транзакций и координаты сохраняются без преобразования в «дополнительных пассажиров».

Официальная документация:

- https://reference.iatistandard.org/en/iati-tools-and-resources/api-gateway/
- https://reference.iatistandard.org/en/iati-tools-and-resources/iati-datastore/how-to-use-the-datastore-api/
- https://reference.iatistandard.org/en/guidance/developer/datastore-and-data-pipelines/
- https://reference.iatistandard.org/en/iati-standard/203/codelists/transactiontype/

## Где держать ключ

Для **первой проверки на сервере** храним его отдельно от Telegram (`bot.token`) и OpenAI (`agent.env`):

`/etc/fca/iati.key`

Разрешения: владелец `root`, группа `agent`, права **0640**. Скрипт выполняется от пользователя `agent`. Ключ не копируется в рабочую директорию агента и не передаётся языковой модели. Передать ключ в чат нельзя.

```bash
# На сервере, после деплоя 0061. Блок прервётся, если ключ уже существует.
sudo bash <<'BASH'
set -euo pipefail
if [ -e /etc/fca/iati.key ]; then
  echo 'Файл /etc/fca/iati.key уже существует; не перезаписываю.'
  exit 1
fi
umask 077
IFS= read -r -s -p 'IATI subscription key (ввод скрыт): ' key </dev/tty
printf '\n' >/dev/tty
[ -n "$key" ] || { echo 'Пустой ключ'; exit 1; }
printf '%s\n' "$key" > /etc/fca/iati.key
chown root:agent /etc/fca/iati.key
chmod 0640 /etc/fca/iati.key
unset key
BASH
```

Обязателен **ключ подписки** с https://developer.iatistandard.org → **Subscriptions** → Exploratory → Primary (либо Secondary). Одной регистрации без активной подписки недостаточно. Не путать ключ IATI с OpenAI.

На Mac можно работать вообще без сервера: `~/.config/flightcost/iati.key`, права `0600`. Для него `--key-file` указывать не нужно. Не помещайте его в `~/Downloads` и не коммитьте.

## Проверка: один запрос

```bash
# На сервере: установленный 0061 уже находится в /srv/fca/app после деплоя.
sudo -u agent /srv/fca/venv/bin/python \
  /srv/fca/app/research/demand-2026-11/investments/iati_fetch.py \
  --key-file /etc/fca/iati.key --probe --countries KE
```

Ожидаем: `IATI API OK | country=KE | matching=N | key: accepted`. Если 401 — проверь подписку/ключ. Если 403 — статус подписки/квоту. `--probe` **не сохраняет** ответ и использует один запрос.

## Первый пилот: Кения, Танзания, Марокко, Египет, Эфиопия, Кабо-Верде

```bash
sudo install -d -o agent -g agent -m 0750 /srv/fca/agent/research/iati

sudo -u agent /srv/fca/venv/bin/python \
  /srv/fca/app/research/demand-2026-11/investments/iati_fetch.py \
  --key-file /etc/fca/iati.key \
  --countries KE,TZ,MA,EG,ET,CV \
  --rows 30 --max-pages 1 \
  --out "/srv/fca/agent/research/iati/$(date -u +%Y%m%dT%H%M%SZ)"
```

Вывод укажет `candidates=...`, `calls=6`, для каждой страны — `retrieved / matched`. **`PARTIAL SAMPLE` не означает, что все проекты страны собраны.** Первый пилот специально ограничен для проверки структуры и нагрузки. Не запускайте несколько пилотов параллельно: учитывайте ограничения Exploratory.

Создаются файлы в новой папке:

- `manifest.json` — срез, источники, число запросов, доля выгрузки, SHA-256 ответов; **без ключа**;
- `candidates.jsonl` — одна строка на **уникальную опубликованную версию активности**; при конфликтующих версиях одного `iati-identifier` будут отдельные помеченные строки. Списки географий, секторов, транзакций и бюджетов сохраняются раздельно;
- `raw/*.json.gz` — оригинальные полученные страницы без ключа, для независимой проверки и последующих сравнений с новыми редакциями;
- `identifier_conflicts.json` (только при конфликтах) — очередь идентификаторов, для которых IATI вернул разные исходные версии; суммы из них запрещено объединять.

Данные публичны, но это **исследовательские рабочие файлы**, не добавляйте их в Git или `data/prices`, не отправляйте модели автоматически. Для передачи на анализ достаточно архива каталога `iati/ДАТА` (он не содержит ключа) либо только `manifest.json` и `candidates.jsonl`.

## Что именно извлекаем

| Поле | Зачем | Главное ограничение |
|---|---|---|
| IATI identifier, reporting org | Устойчивый ключ внутри IATI | Один реальный проект может иметь несколько IATI activity IDs |
| Сектор + vocabulary, страны + проценты | Классификация и география | В смешанном проекте нельзя приписать всю сумму одному городу |
| Локации и точность | Подбор вероятных аэропортов | Точка может означать город/регион, а не стройплощадку |
| `outgoing_commitment` | Юридически оформленное обязательство | Не равно уже перечисленным деньгам |
| `disbursement` и `expenditure` | Фактический ход финансирования | Не равно вводу завода/отеля в эксплуатацию |
| Budget | Планы финансирования по периодам | Может измениться или не быть реализован |
| `snapshot_at` + исходный JSON | Снимок того, что нам действительно было доступно | Не делает прошлые прогнозы автоматически проверяемыми |

**Риск знания будущего:** данные, впервые сохранённые в 2026 году, нельзя использовать в историческом прогнозе «как будто мы знали их в 2019». Поле `@last-updated-datetime` — дата изменения у публикатора, а не гарантированная дата первой публикации. Для backtest нужны архивные *публикационные версии*.

**Риск дублирования:** IATI и World Bank PPI / AfDB могут описывать один проект; между публикаторами нельзя просто складывать суммы. В этом этапе *вообще нет* итогового CAPEX, объединённого между валютами, стадиями или странами.

## Что будет после первой живой выгрузки

1. Проверим 50–100 содержательных кандидатов: фактическая точность географии, тип объекта, период, бюджет/освоение, задержки и связь с другими базами.
2. Сопоставим с PPI и GEM по названию, координатам, датам и инвестору; вручную разберём спорные совпадения.
3. Найдём архивные версии для честного исторического теста: были ли изменения в пассажиропотоке **после** тех событий, которые в тот момент уже были известны.
4. Подготовим инфографику «проект → дата ввода → зона аэропорта → проверенный авиационный эффект» внутри существующей статьи спроса. В калькулятор эти коэффициенты пока не передаём.

## Исправление 0062

Убраны недокументированные поле `activity_id` и `sort=activity_id asc` из запросов.
При HTTP 400 дополнительно выводится короткая диагностическая ошибка Solr без HTTP-заголовков и ключа.
Для проверки достаточно одного `--probe` с ключом через временную службу systemd и `LoadCredential`.

## Исправление 0063 — один идентификатор, несколько исходных версий

IATI подтверждает, что Datastore иногда возвращает **несколько документов с одним
`iati-identifier`**, если публикатор включил активность в разные исходные файлы:
https://connect.iatistandard.org/post/the-january-2024-release-of-datastore-unified-data-pipeline-13837339

Скрипт раньше завершался с ошибкой `Conflicting source records for the same IATI identifier`,
когда разные документы попадали в одну страницу. Теперь:

1. Исходные ответы в `raw/*.json.gz` сохраняются без изменений.
2. Идентичные исходные активности одного идентификатора не дублируются;
   учитывается число повторов и страны, запросы по которым их вернули.
3. Разные версии активности с одним идентификатором сохраняются в отдельных
   строках `candidates.jsonl`. Каждая имеет `source_variant_sha256`.
4. Каждая конфликтующая строка имеет `identifier_conflict: true` и
   `financial_aggregation_blocked_reason: conflicting_iati_identifier`.
5. `manifest.json` показывает число уникальных идентификаторов, версий,
   повторов и конфликтов. При конфликте создаётся `identifier_conflicts.json`.

**Ни одна из конфликтующих версий не выбирается «правильной» автоматически.**
Не суммируйте их транзакции и бюджеты. Для этого нужен отдельный просмотр
исходных файлов публикатора и, при необходимости, уточнение у IATI.

Если старый запуск 0061/0062 уже остановился на конфликте, его каталог с
`raw/KE-000.json.gz` является **незавершённым снимком**: там нет итогового
`manifest.json`. Не используйте его как набор данных. Повторите ограниченный
запуск после деплоя 0063 в новой папке. Это потребует один новый API-запрос.
