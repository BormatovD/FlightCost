# Наблюдение за тарифами на VPS FlightCost

Отдельный staging-процесс на VPS. Четыре таймера systemd используют имеющиеся бесплатные источники. Операционный калькулятор и рабочая база сайта к этому процессу не подключены.

| Служба | Расписание VPS, UTC | Результат |
|---|---|---|
| `fca-fo@tickets` | Каждые 3 минуты на VPS. До 120 направлений за запуск. | Цены прямых билетов в одну сторону в USD из кэша Aviasales. Для каждого результата сохранены запрошенные коды, фактические аэропорты и время вылета. Если вернулось 1 000 элементов, партия имеет статус `partial` и считается только первой страницей. |
| `fca-fo@charges` | Каждый час. До 8 ссылок за запуск. | PDF и HTML публикаций аэропортов и регуляторов с датой получения, кодами аэропортов и хешем. Из 52 записей в очереди 48 содержат HTTPS-адреса для обхода. В трёх записях AERA и одной записи Eurocontrol указаны опорные страницы с текстовым примечанием о документе. Эти ссылки оставлены для уточнения. |
| `fca-fo@discovery` | В 03:17 с небольшим разбросом. | Поиск открытых источников через публичную выдачу и официальные каталоги, в том числе по опубликованным данным о средних фактически уплаченных тарифах. Третий поисковый запрос проходит по 22 регионам по очереди. Каждая принятая ссылка отдельно открывается. В staging сохраняются карточка кандидата и снимок первоисточника с SHA‑256. |
| `fca-fo-ingest` | Каждые 5 минут. | Импорт JSON из трёх outbox после проверки схемы, границы outbox, размеров и SHA-256 вложений. Технически отказавшие запросы остаются в журнале без наблюдений. |

Поисковый агент — отдельный скрипт: публичная выдача Bing RSS, открытый каталог GOV.UK и переходы по ссылкам в официальных каталогах, включая ANAC и DOT. Выдача ограничена, некоторые сайты возвращают 403, а релевантность и полнота поиска по странам не гарантированы. Используется только бесплатный кешированный Data API Travelpayouts с существующим ключом. Платных Flights Search API, поисковых API с тарификацией, API моделей и подписок в конфигурации нет.

Время старта сдвигает `RandomizedDelaySec`. Точные следующие запуски приводит `systemctl list-timers 'fca-fo-*.timer'`.

Интервал билетного таймера указан в `units/fca-fo-tickets.timer`. На VPS с 23 ноября действует переопределение `60-collection-frequency.conf` с тем же интервалом. Обновление состава очереди добавляет новые ключи в непустую очередь и сохраняет статусы и сроки повторных проверок исходных направлений.

## Что считается свидетельством

- Билет — единичное предложение из кэша. Результат `empty` означает, что в ответе кэша не было записей. `filtered` означает, что вернулись записи и ни одна не прошла проверку. HTTP 401, 403 или 429 завершает текущую билетную партию с записью результата. Такие статусы не превращаются в ноль пассажиров или цену.
- Билетное направление получает `unsupported_route`, если Aviasales отвечает HTTP 400 и сообщает, что код пункта неизвестен, аэропорт не обслуживается по этому API или коды обоих пунктов приводятся к одному городу. Для повторной проверки используйте `tickets --probe AAA-BBB`. Корректный успешный ответ возвращает направление в автоматическую очередь. Остальные HTTP 400 сохраняют статус `http_400` и для активного направления повторяются по обычному расписанию ошибок. Карточка ошибки содержит код направления, время, итоговый статус и нулевое количество записей.
- Публикация о сборах — сохранённый PDF/HTML. Её статус отражает факт получения. Извлечение ставки, периода действия, условий и проверка пригодности к импорту в калькулятор требуют отдельной обработки. Документы сохраняются по SHA‑256.
- Найденный источник — карточка со статусом `candidate`, доменом издателя после перенаправления, временем получения и коротким фрагментом из самого документа. Дата публикации извлекается из однозначных метаданных. Срок действия, валюта и единица заполняются только по однозначным фразам документа или метаданным обозначенного набора. При отсутствии сведений поля имеют значение `null`. Для консультаций даты обсуждения, суммы в тексте и упоминания сборов не трактуются как срок действия, валюта или единица тарифа. Новые поисковые и каталоговые ссылки остаются `unclassified` до проверки. Ставки по найденным документам не извлекаются. HTML и CSV читаются напрямую. У PDF используется читаемый заголовок из встроенных метаданных, а попытка без читаемого фрагмента остаётся в журнале как `invalid_response`.
- Для оценки оплаченной цены пригодность определяется определением источника. Например, у ANAC существуют исключения по льготным билетам, у таблиц DOT свой географический и маршрутный охват, а серия BITRE отражает предложения. [Aviasales](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API) · [ANAC](https://www.anac.gov.br/acesso-a-informacao/dados-abertos/areas-de-atuacao/voos-e-operacoes-aereas/tarifas-aereas-domesticas/46-tarifas-aereas-domesticas) · [DOT](https://data.transportation.gov/Aviation/Consumer-Airfare-Report-Table-1-Top-1-000-Contiguo/4f3n-jbg2/about_data) · [BITRE](https://www.bitre.gov.au/resource/aviation/domestic-airfares).

## Как устроена изоляция

У каждого потока отдельный системный пользователь и закрытая рабочая папка `/var/lib/fca-fo-…`. В `/var/spool/fca-fare-observer/<поток>` пишет только соответствующий пользователь. Импортёр читает outbox через отдельную группу с правом чтения и без доступа на запись. У импортёра отдельная папка и нет доступа к IP-сокетам. В пространствах имён наблюдателя закрыты `/srv/fca`, общий `/etc/fca`, конфигурация сайта в Caddy, служебные файлы рабочих unit и домашние каталоги. Исполняемые файлы принадлежат root. Перед каждым запуском [программа проверки](boundary_check.py) действует под UID соответствующей службы внутри того же systemd sandbox: открывает пробный файл в своём outbox и проверяет отказ чтения и записи в чужих зонах, чтения общих конфигураций и записи системного кода. В журнал попадают роль и UID, значения секретов не читаются проверкой.

Ключ Travelpayouts находится в `/etc/fca-fare-observer/ticket-token` с правами 0600 для root. Systemd открывает его только билетной службе как credential. Ключ передаётся заголовком одному зафиксированному HTTPS-адресу без перенаправлений. В рабочих журналах, outbox, staging и файлах релиза ключа нет. Для общего поиска ключей нет.

Передача данных использует атомарную запись JSON и SHA-256 для приложений. Для билетов и сборов сохраняется версия 1. Для поиска используется версия 2 с полями `status`, `publisher_domain`, `fetched_at`, `published_on`, `valid_from`, `valid_until`, `currency`, `unit`, `excerpt` и `format` в дополнение к прежней ссылке, описанию, хешу и размеру. Старые карточки версии 1 читаются без изменения и без добавления сведений задним числом. Общие поля — `version`, `stream`, `checked_at`, `target`, `status`, `raw_count`, `items`. Схема каждого вида зафиксирована в [evidence.py](evidence.py). Валидатор открывает только обычные файлы из конкретного outbox, отклоняет символические ссылки, неверный поток и некорректные поля. Дубликат имени не вызывает повторного импорта. Результат сохраняется в `/var/lib/fca-fo-ingest/staging.sqlite3`. Таблица `handoff` содержит результаты попыток, представление `evidence` — принятые свидетельства, папка `documents` — содержимое публикаций о сборах, а `candidate-documents` — снимки первой загрузки поисковых источников, адресованные по SHA‑256. Перед импортом версии 2 валидатор сверяет размер и хеш снимка, затем извлекает из него фрагмент и метаданные и проверяет совпадение с карточкой.

## Воспроизведение и проверка

Очередь собрана [build_queue.py](build_queue.py) в `outputs/forecast-fare-observer/queue.json.gz`. Для переноса на чистый хост сложите рядом с [install-vps.sh](install-vps.sh) `observe.py`, `evidence.py`, `candidate_source.py`, `boundary_check.py`, `flightcostapp/ticket_controls.py` (как `ticket_controls.py`), `queue.json.gz` и каталог `units/`. Скрипт установки запускается на VPS от root. Положите существующий ключ защищённым каналом в файл credential, выставив права root:root 0600. Запустите три службы вручную, затем импорт и [verify-vps.sh](verify-vps.sh). Для автоматической работы включите таймеры `fca-fo-tickets.timer`, `fca-fo-charges.timer`, `fca-fo-discovery.timer`, `fca-fo-ingest.timer`. Скрипт проверки выводит агрегаты и публичные ссылки.

Результаты проверки VPS и расписания сохраняются в рабочем файле `outputs/forecast-fare-observer/vps-verification.txt`. Покрытие зависит от доступности публикаций и наполнения кэша. История накапливается в закрытом staging.
